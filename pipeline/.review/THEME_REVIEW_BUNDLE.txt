You are a senior product designer and frontend engineer reviewing a
Shopify storefront theme for a dropshipping store ("Wanelo"). The
site sells $15-30 EPROLO-imported products with cold paid traffic
(Meta/TikTok ads). The product description on every product page is
auto-generated by an AI pipeline that writes JSON into ~21 Shopify
metafields per product. The theme renders each metafield via one
Liquid snippet (skip-if-blank — empty metafield = section hidden).

GOAL OF YOUR REVIEW
─────────────────────
Modernize the design to 2026 high-conversion e-commerce standards.
Identify weak visual hierarchy, dated patterns, mobile UX gaps,
typography problems, and color-usage mistakes. Output PRECISE,
file-by-file change suggestions the engineer can paste back without
needing design intuition.

KEY CONTEXT (don't reinvent — adjust within constraints)
─────────────────────
• Per-product pastel palette injected as CSS variables (--brand-1,
  --brand-2, --brand-3, --brand-soft, --brand-deep) from
  product.metafields.custom.palette JSON. Palette varies per product
  but always pastel (luminance 0.55-0.95, saturation < 50%).
• Master Liquid section `wanelo-product-page` renders 21 snippets in
  funnel order on every PDP. Snippets with empty metafields skip
  themselves via Liquid `if metafield.value != blank` guards.
• Body copy is editorial (warm-confidant / witty / clinical /
  editorial-thoughtful / aspirational-luxury / down-to-earth tone
  enum). H1 / kicker / lead are AI-written per product. Stats use
  specific numbers ("35dB quieter than fridge"), not vague claims.
• Single shared wanelo.css (~519 lines) + wanelo.js (sticky mobile
  ATC + IntersectionObserver reveal animations).
• Already implemented: lazy-load below-fold images, sticky mobile
  ATC bar, hero inline CTA mirror, hero trust line under H1.

WHAT TO ASSESS (rate each: 🟢 good / 🟡 weak / 🔴 dated)
─────────────────────
1. Visual hierarchy across the 21-section funnel.
2. Typography system (font family, scale, weights, line-height).
   Currently using `Fraunces` (serif italic for emotional words via
   <em>) but no explicit primary font declaration — relies on theme
   inheritance. Suggest a 2026 type system.
3. Spacing rhythm (padding, gap, max-width). Many sections use
   padding 48-64px 24px; max-width 1100px.
4. Color usage. Palette is pastel-only by design but everything
   defaults to var(--brand-*) — could feel too soft / lacking
   contrast for CTA buttons.
5. Animations / motion. Currently only reveal-on-scroll. Modern
   sites use micro-interactions, magnetic buttons, scroll-linked
   parallax, etc. Suggest what makes sense for high-CVR PDP
   (not gimmicky).
6. Mobile layout — many snippets use grid-template-columns: 1fr on
   mobile, multi-column from 760px+. Check responsive breakpoints.
7. Component density — 21 sections may be too much. Should some
   merge / be removed? Should we add a TOC / quick-nav?
8. CTA prominence + button styling. Currently 1 main CTA at bottom
   (wanelo-cta) + inline CTA in hero + sticky mobile ATC.
9. Card / chip / pill styles — consistent? Modern?
10. Glass-morphism / brutalist / minimal / editorial — what AESTHETIC
    DIRECTION should this take? Suggest one with rationale.
11. Accessibility (focus rings, aria labels, color contrast).
12. Page weight / performance (one CSS file ~25 KB, one JS ~1.5 KB).

HARD CONSTRAINTS — do NOT suggest changing these
─────────────────────
• Module set & order: don't propose adding/removing modules. The 21
  metafields are fixed by the AI pipeline.
• Shipping / returns / secure-checkout — these are intentionally
  ABSENT from the storefront design. They're handled in a separate
  Shopify checkout-page module the operator manages separately. Do
  NOT add risk-reversal / guarantee / shipping-info modules to the
  PDP design.
• Skip-if-blank gates — preserve them. Don't add hardcoded fallback
  content.
• Per-product CSS variables (--brand-1, --brand-soft, etc.) — keep
  them as the palette source of truth.
• Liquid syntax — output must remain valid Shopify Liquid.

🛑 SKIP THESE (being removed, do not review)
─────────────────────
• snippets/wanelo-guarantee.liquid — entire file is being deleted
  (operator handles risk reversal in a separate Shopify checkout
  module).
• snippets/wanelo-hero.liquid lines 28-29: the `wanelo-hero__trust`
  div with default "30-day returns · Free shipping · Secure
  checkout" — being removed for the same reason.
• In wanelo.css: the `.wanelo-hero__trust` rules (lines 471-475) and
  the entire `.wanelo-guarantee` / `.wanelo-g-grid` / `.wanelo-g-item`
  block (lines 490-503) — being removed.

When you propose new aesthetic direction, do NOT add similar trust /
guarantee / shipping modules back. Those concerns live on the
checkout page, not the PDP.

OUTPUT FORMAT
─────────────────────
For each file you suggest changes to, output a section:

  ### FILE: <path>
  CURRENT ASSESSMENT: <one-paragraph review>
  CHANGES:
  - line/section reference: change X to Y because Z
  - ...
  NEW SNIPPET (if rewriting):
  ```liquid|css|js
  ...full replacement...
  ```

ALSO produce a top-level "OVERALL DESIGN DIRECTION" block at the
start: 3-5 bullets describing the new aesthetic + 1 sentence on
expected CVR/UX impact.

OUTPUT FORM PREFERENCE
─────────────────────
Operator wants OPTION B from your earlier offer: an interactive HTML
review page where each file's diff is collapsible / side-by-side
before/after, with the new aesthetic direction previewed as a live
mock. The mock should let the operator click through a fake product
page (fake palette + fake data injected) so they can SEE the new
design before approving instructions for the engineer.

If that's not feasible in your environment, fall back to OPTION A
(Markdown document) with embedded CSS/HTML preview snippets the
operator can paste into a Shopify theme preview.

Be specific. Prefer exact CSS/Liquid edits over high-level
"feedback". Assume the engineer applying your changes has no design
intuition — they need precise instructions.

// WANELO storefront JS — reveal-on-scroll + mobile sticky ATC.
// Two concerns kept in one file (~1 KB minified) so theme only loads
// one extra asset.
(function () {
  if (!('IntersectionObserver' in window)) return;

  // ── Reveal-on-scroll: adds .in to .reveal / .mask when entering viewport.
  var revealIO = new IntersectionObserver(function (entries) {
    entries.forEach(function (e) {
      if (e.isIntersecting) {
        e.target.classList.add('in');
        revealIO.unobserve(e.target);
      }
    });
  }, { threshold: 0.1, rootMargin: '0px 0px -8% 0px' });
  document.querySelectorAll('.wanelo-page .reveal, .wanelo-page .mask').forEach(function (el) {
    revealIO.observe(el);
  });

  // ── Mobile sticky ATC: when the real product form scrolls off-screen on
  // mobile (<769px), pin a CTA bar to the bottom of the viewport. Tapping it
  // smooth-scrolls back to the form. One-tap re-access from anywhere on
  // page = +15-25% mobile CVR.
  function setupStickyAtc() {
    if (window.matchMedia('(min-width: 769px)').matches) return;
    var form = document.querySelector('form[action*="/cart/add"]');
    if (!form) return;
    if (!form.id) form.id = 'wanelo-atc';

    var bar = document.createElement('a');
    bar.className = 'wanelo-sticky-atc';
    bar.href = '#' + form.id;
    bar.setAttribute('aria-label', 'Jump to add to cart');
    bar.innerHTML = '<span class="wanelo-sticky-label">Add to cart</span>'
      + '<span class="wanelo-sticky-arrow" aria-hidden="true">↑</span>';
    document.body.appendChild(bar);

    bar.addEventListener('click', function (ev) {
      ev.preventDefault();
      var target = document.getElementById(form.id);
      if (target) target.scrollIntoView({ behavior: 'smooth', block: 'center' });
    });

    var stickyIO = new IntersectionObserver(function (entries) {
      entries.forEach(function (e) {
        if (e.isIntersecting) bar.classList.remove('visible');
        else bar.classList.add('visible');
      });
    }, { threshold: 0.05 });
    stickyIO.observe(form);
  }

  if (document.readyState === 'loading') {
    document.addEventListener('DOMContentLoaded', setupStickyAtc);
  } else {
    setupStickyAtc();
  }
})();
