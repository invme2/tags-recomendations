# Ozon-style IA & SEO-силос для wanelo.com — план

> Автор: IA-инженер. Цель — повторить логику Ozon (faceted-категории +
> attribute-лендинги + плотная ранжированная перелинковка), чтобы ловить
> long-tail спрос («умные часы с тонометром», «лампы для маникюра белые»)
> и распределять link-equity по каталогу.

---

## 0. TL;DR — что строим
Трёхслойный силос:
1. **Иерархия категорий** (5 уровней) с хлебными крошками по primary-пути.
2. **Attribute-лендинги** (листья) = коллекции под конкретные поисковые запросы,
   создаём ТОЛЬКО под запросы с реальным спросом (DataForSEO).
3. **Перелинковка**: PDP→attribute-коллекции (spec-ссылки), коллекция→соседи
   (ранжированные чипы), хлебные крошки (один primary-путь).

---

## 1. Целевая модель иерархии (5 tiers)
| Tier | Что | Пример | У нас |
|---|---|---|---|
| **T1** Department | верх | Красота и здоровье | `parent_category` (расширить) |
| **T2** Category | | Маникюр и педикюр | из таксономии (cluster.section) |
| **T3** Subcategory | | Оборудование для маникюра | из таксономии (cluster) |
| **T4** Product-type «хаб» | тип товара | Лампы для маникюра | главные keyword-коллекции |
| **T5** Attribute «лист» | запрос | Лампы белые / UV-LED / 48W | 🆕 **создаём** |

Каждой коллекции — метафилды: `tier` (T1–T5), `parent_handle` (родитель в дереве),
`query` (поисковая фраза-цель страницы).

---

## 2. Типы страниц — что где показывать
| Tier | Хлебные крошки | Верхние чипы «подборки» | Левый сайдбар | SEO-копирайт |
|---|---|---|---|---|
| T1–T3 (широкие) | путь сюда | **НЕТ** attribute-чипов | дерево подкатегорий | интро категории |
| T4 (хаб) | полный путь | ранжированные **соседи** (silo) | фасеты + дети T5 | гайд по выбору |
| T5 (лист) | полный путь + лист | ранжированные соседи/листья | фасеты | интро под запрос |

**Правило (твоё наблюдение):** attribute-чипы/ссылки — только на T4/T5, не на широких T1–T3.
Верхние чипы = **коллекции-соседи по родителю** (навигация-перелинковка), НЕ варианты текущей.

---

## 3. Страница товара (PDP)
- **Чипы вариантов** (Color/Size) сверху — рендерит тема.
- **«О товаре» — куцая таблица** (топ 6–8 ключевых атрибутов из factual specs).
  Значения **кликабельны** → ведут на T5 attribute-коллекцию, ЕСЛИ под этот
  запрос есть виабельная коллекция; иначе — просто текст (как у Ozon).
- **«Перейти к характеристикам»** → полная secция `Specifications` (все атрибуты).
- **Хлебные крошки** = ОДИН primary-путь товара (`primary_collection` → его T-цепочка),
  не все коллекции, в которых лежит товар.

---

## 4. Создание attribute-лендингов (T5) — ядро новой работы
1. **Источник атрибутов:** factual specs (EPROLO-скрейп, бэкафилл) + теги. Чистые
   канонические значения (Material, Color, Type, Power, Skin Type, Scent…).
2. **Кандидаты-запросы:** `<product-type> + <attribute value>`
   (напр. «nail lamp» + «UV-LED» → «UV-LED nail lamps»). Мульти-значения дробим.
3. **Гейт по спросу (DataForSEO):** оставляем только запросы с реальным volume
   (≥ порог) и приемлемым KD. Остальные → просто текст, страницу НЕ создаём.
   Это и есть «умный отбор» Ozon.
4. **Дедуп vs существующие 1058:** есть коллекция → ссылка; нет → создать.
5. **Создание = smart-коллекция** (правило: tag/attribute = value) → авто-наполнение,
   без ручной курации. Метафилды tier=T5, parent=T4-хаб, query=title.
6. **Анти-thin guard:** не создавать если < N товаров подходит, или volume низкий.
   Кап на общее число новых коллекций.

---

## 5. Перелинковка и ранжирование
- **Spec-слой:** значения в PDP-таблице → T5-коллекции.
- **Слой соседей:** на странице коллекции — ранжированный ряд related из того же
  силоса. Апгрейд `_compute_collection_related`: добавить **вес спроса**
  (DataForSEO volume) к TF-IDF близости + кластер.
- **Хлебные крошки:** один primary-путь на товар/коллекцию.
- **Хаб→листья:** T4-хаб перечисляет свои T5-дети.

---

## 6. SEO-гардрейлы (критично)
- **Volume-гейт создания** — никаких thin/doorway-страниц.
- **Канонизация:** каждый attribute-лист canonical на себя; НЕ плодить
  cross-product (цвет×мощность) — одна ось на страницу, не декартово произведение.
- **Краул-бюджет:** кап листьев на хаб; very-thin → noindex.
- **Уникальный копирайт** на каждый лист (короткий, под запрос).

---

## 7. Фазы внедрения
| Фаза | Что | Статус |
|---|---|---|
| **P0** Фундамент | factual specs у всех товаров (бэкафилл) | ⏳ идёт |
| **P1** Иерархия | разметить каждой коллекции tier+parent (дерево из parent_category + таксономии); логика primary-крошки | next |
| **P2** Прототип | 1 категория (Лампы): атрибуты → запросы → DataForSEO → создать T5 + spec-ссылки + чипы → **ревью** | gated |
| **P3** Масштаб | прогон P2 по всем категориям, volume-gated | |
| **P4** Ранжирование | вес спроса в related-чипах | |
| **P5** PDP-раскатка | spec-таблица (куцая+кликабельная) на всех товарах | |

---

## 8. Решения, нужные от владельца
1. **Порог volume** для создания листа (напр. ≥ 100/мес? ≥ 50?).
2. **Макс листьев на хаб** (напр. 10–20?).
3. **Какие оси фасетить** по категориям (Color? Material? Power? Skin Type?).
4. **Одна ось или комбинации** (белые лампы vs белые-48W лампы — рекомендую ОДНА ось).
5. **Бюджет DataForSEO** на проверку кандидатов (тысячи запросов = $).

## 9. Наши активы (отправная точка)
- 1058 коллекций (DataForSEO keyword, плоско) + `parent_category`.
- `primary_collection` на товарах; теги (таксономия 765 кластеров: cluster/persona/intent/demo).
- `_compute_collection_related` (TF-IDF+кластер) + `wanelo-collection-related.liquid` (ряд чипов) — слой соседей УЖЕ есть.
- factual specs (EPROLO, бэкафилл ~30% + растёт) + Designer specs (51%).
- DataForSEO (5 endpoints) для volume/KD.
- Тема: breadcrumbs-секция, wanelo-specs, wanelo-collection-related.

---

## 10. Реалистичная оценка
Ozon строил это годами с отделом IA. Мы делаем **прагматичную версию**: 5 tiers,
volume-gated attribute-листья, переиспользуем существующий слой соседей. Точное
1-в-1 не цель — цель захватить long-tail и силос-перелинковку без thin-page штрафов.
